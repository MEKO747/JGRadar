# 实验台账（JGRadar 雷达站）

维护：研究员。**只记录，不改代码、不改训练/运行配置，不替程序员与调研员下统计结论。**
论文里出现的每一个数字，都必须能指回本目录的一条记录；指不回来的数字不许进正文。

## 一条记录写什么

文件名 `YYYY-MM-DD.md`，条目编号 `R01`、`R02`…（按时间追加，不改旧条目）。
每条固定五栏，缺哪栏就写"无"，不许省略：

| 栏 | 内容 |
|---|---|
| 时间 | 日期 + 时刻（本机 Asia/Shanghai） |
| 操作与命令 | 实际跑的命令；只读静态代码的写"静态阅读 + 文件:行" |
| 证据指纹 | `git rev-parse HEAD`、配置文件 sha256、数据路径 / sha256 |
| 结论 | 一句话能站住的结论；数字带口径（哪个层级、分母是什么） |
| 反例与风险 | 这次结果**不能**证明什么；已知的混杂因素 |

结论被推翻时**不删旧条目**：新增一条，写"推翻 Rxx"，旧条目保留原样。

## 口径纪律（血泪换来的）

1. **帧/秒必须说清是哪一级**：`比特 → 空口帧 → 序列帧 → 业务包`，四级的速率差一个量级，
   写"31 帧/秒"不说层级等于没写。`tools/radio_probe.py` 的四种报告口径就按这四级分。
2. **"准确"是规则定义，不是统计定义**：2027 规则按**逐次**发送判 `d<0.8m` 为准确，
   P95 只是我们自己加的工程统计口径。论文里两个都要写，且必须分开说。
3. **数据源要标清**：空口收到的信息波业务包当前是**随机测试发生器**的数据
   （帧合法、帧间不连贯），不是真实赛场数据。凡拿它算"定位误差"都是错的。
4. **合成输入 ≠ 真实链路**：ZMQ 注入的协议字节流验证的是解析与仲裁，不是射频；
   回放 fixture 预置的检测结果验证的是跟踪与融合，不是相机与模型精度。
5. **未落盘的口头结论**标"群内口头，未落盘"，不进正文，只进"待补实验"。

## 证据分级（2026-11-21 起执行）

台账里的每一份证据必须标一级，级不够的不许进阶段验收表：

| 级别 | 含义 | 能进验收表 | 典型例子 |
|---|---|---|---|
| **A 真机** | 目标硬件 + 真实信号/真实场景 + 真值 | ✅ | 空口真实信号 + 已知点真值算出的 `d` |
| **B 离线真实数据** | 真实录制（IQ/录像）+ 离线回放 | ✅（注明「离线」） | 用现场 IQ 重放解码、真实录像跑跟踪 |
| **C 合成回放** | 夹具/合成数据，链路真跑 | ❌ 只进「方法/管线验证」 | 96 帧 fixture 的 `tier_share`、B1 故意丢帧 |
| **D 单元/假时钟** | 单测、注入时钟 | ❌ 只进「实现正确性」 | 4.7Hz 静默节拍、P 模型官方算例 |

**内置 UVC 摄像头一律不算视觉证据**：它能证明「取图 → 检测 → 跟踪 → 发布」管线不断（C/D 级），
证明不了检测精度、标定与机位。**内置 UVC 的结果不进任何验收表，也不许写成「视觉验证通过」。**
同理，`stub` 检测后端、无身份的槽位全 MISSING，都只能算管线验证。

**占位配置不是标定**：`config/camera.yaml` 当前是占位（`name: unselected`、`dist` 全 0、外参单位阵、
`reproj_rms_px: null`，文件头自述「相机尚未选型」）。标定证据必须同时给出：
① 相机型号与序列号；② 本机重标日期与棋盘图；③ `reproj_rms_px` 实测值；④ 标定文件 sha256。
缺任一项，该条视觉结果只能记 C/D 级。

### 反例：`providers` 列表 ≠ 实际计算位置（B 级也要验字段完整性）

2026-11-21 的实例：`out/gpu_bench_20261121/e2e_20261121_0125*.json` 里只有
`providers: ["CUDAExecutionProvider", "CPUExecutionProvider"]`，**没有** `fell_back_to_cpu`，
也没有「每个 provider 实际分到多少节点」。而 ORT 的行为是：**CUDA EP 建起来了、却一个节点都没分到，
`get_providers()` 照样把 CUDA 列在最前面。** 所以那份 JSON 单看文件，**无法自证这 54ms 是 GPU 算的**。

这不是精度问题，是**证据字段完整性**问题——等级再高，字段缺了也站不住：

1. 一批数里「实际计算位置」必须能从文件本身读出来，不能靠「我记得当时是 GPU」；
2. 性能/加速类数字（无论 A 还是 B 级）必须同时带：实际 provider、节点分配、是否回退、commit、配置哈希；
3. **CUDA 节点数为 0 时应直接失败（非零退出码）**，宁可不交数，也不交一个看不出真假的数。

> 由此推广：**A/B 级证据也要验字段完整性**。真实录制的回放如果没记 provider、commit、配置哈希，
> 它只是「一次观察」，同样不进验收表。等级管「数据真不真」，字段管「这份记录能不能自证」，两者都要过。
