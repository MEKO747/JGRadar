# 被标记进度 P(t)：模型与过期策略对比

这段是**离线评估**，不进实时链路。目的有两个：给论文的「评估方法」一节一个可复算的
模型，以及回答一个工程问题——雷达断流时，`0x0305` 该发 `(0,0)` 还是发旧值。

## 模型来源

逐字实现《RoboMaster 2027 机甲大师超级对抗赛比赛规则手册 V1.0.0》（20261015）
§5.7.4 表 5-29，**没有任何自拟参数**：

| 标记状态 | x 的更新 | P 的更新 |
| --- | --- | --- |
| 准确 `d<0.8m` | 上一次准确/半准确 → `x=x+1.0`；否则 `x=1.0` | `P=P+x` |
| 半准确 `0.8≤d<1.6m` | 上一次准确/半准确 → `x=x+0.5`；否则 `x=0.5` | `P=P+x` |
| 错误 `d≥1.6m` | 上一次错误/中断 → `x=x−0.8`；否则 `x=−0.8` | `P=P+x` |
| 数据中断 | 每累计 **0.5 秒**未收到数据 = 一次「错误」判定 | 同上 |

`P` 限幅 `[0,150]`。判定频率 = 雷达发送频率（我们 4.7Hz）。

**验收线是规则手册第 112 页那段算例**：5Hz、100% 准确 15 拍 → `1,3,6,10,15…`，
3.0s 到 120；随后 0% 准确 → `119.2,117.6,115.2,112,108`；断流 1 秒 → `103.2,97.6`；
再两次准确 → `98.6,100.6`。`tests/test_marking_progress.py` 把这串数字全部钉死。

## 两个容易看错的地方

1. **`x` 是动量，不是计分器**。连续准确时它线性增长，`P` 因此二次增长；一次中断或
   一次错误会把 `x` **打回 −0.8**（不是减掉 0.8），前面整段累积归零。断流的代价不是
   "少 0.8"，而是"重新从 1.0 开始爬"。
2. **4.7Hz 冷启动很快**：`P≥100` 要 14 拍 ≈ 2.98s（从第一帧起算 2.77s），
   `P≥120` 15 拍。所以"连续 3 秒准确"是个可以直接拿去赛场验证的强预测。

## 过期策略对比

工具：`tools/marking_sim.py`（合成场景网格 + 真实日志两种模式）。

```zsh
.venv/bin/python tools/marking_sim.py --mode grid --out out/marking_sim/20261121
.venv/bin/python tools/marking_sim.py --mode log --referee-log out/referee_0305.jsonl \
    --slot B1 --speed-mps 2.0 --out out/marking_sim/log_20261121
```

**结论是条件句，不是"drop 更好"**：

| 情况 | 该发什么 | 理由 |
| --- | --- | --- |
| 旧坐标仍在 1.6m 内（准确或半准确） | `send_stale` | 半准确继续 `x+0.5` 累积，`P` 还在涨；`drop` 反而把 `x` 打回 −0.8 |
| 旧坐标已 ≥1.6m | `drop` | 一旦判错 `x` 归零，且 `send_stale` 是按发送频率判错（≈2.35 倍判定次数） |
| 断流短于 0.5 秒 | `drop` | 连中断都触发不了，几乎零代价 |

本仓库默认 `drop`，是"不知道目标跑没跑"时的保守选择，不是最优解。按速度切换策略
需要速度估计，记在 backlog，未做。

## 局限（必须写进论文）

- **数据是合成场景**：匀速直线 + 固定种子噪声 + 人为断流窗口，不是赛场录制。
- 结论口径是「断流结束后 0.5 秒的 P」；秒数依赖场景假设（延迟 0.2s、噪声 0.1m）。
- 真实日志模式可以吃 `run_radio_vision --referee-log` 的输出，但**没有真值**，只能
  验证管线，不能产出准确率结论。
- `0x020C` 是 1Hz 布尔快照，只能对齐"阈值穿越时刻"，不能反推 P 曲线。
